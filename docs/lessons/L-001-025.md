# Lessons — shard 1: L-001…L-025

Append-only lessons log, **25 entries per shard** (D-023). Rules and index live in
`docs/LESSONS.md`. Entries are never edited — a wrong lesson is corrected by a new entry.

---

### L-001 — the `libs` version-catalog accessor is out of scope inside `subprojects {}` `build`
Symptom: *"Extension with name 'libs' does not exist"* from a root `subprojects` block.
Cause: Gradle generates the catalog accessor per build script; inside `subprojects` the
receiver is a subproject that has no such extension. Fix: capture catalog values at root
scope into `val`s and reference those inside the block, or use a `buildSrc` convention
plugin (where the problem disappears entirely). Learned: session 2 (T-001).

### L-002 — this machine's `grep` is `ugrep` and misparses some flag combos `tooling`
`grep -vF '-'` silently misbehaves. Fix: invoke `/usr/bin/grep` explicitly, or prefer
Python for text processing in scripts meant to be portable. Learned: session 2.

### L-003 — `ls -la` can hang in this environment `tooling`
A shell alias intercepts it. Use `/usr/bin/ls` or `/usr/bin/find`. Learned: session 2.

### L-004 — no `gradle`/`mvn` on PATH; regenerate the wrapper from the cached dist `build`
`JAVA_HOME` is unset and no Gradle is installed — the wrapper is the only entry point. To
regenerate it, invoke the cached distribution directly:
`~/.gradle/wrapper/dists/gradle-9.7.1-bin/*/gradle-9.7.1/bin/gradle wrapper`.
Learned: session 2 (T-001).

### L-005 — `V` is legal only as a method return type, never a field type `jvm-spec`
JVMS §4.3.2–§4.3.3: `V` (void) appears only as a MethodDescriptor's return; a
FieldDescriptor may never be `V`. The first field-descriptor round-trip test wrongly
included `V` — the *test* was wrong, not the parser. Rule: when testing against a spec,
check the spec section; do not generalise from familiar syntax. Learned: session 3 (T-002).

### L-006 — `LFoo;` is ambiguous between a field signature and a class signature `jvm-spec`
JVMS §4.7.9.1: a FieldSignature (`LFoo;`) is also a valid parameterless ClassSignature
(superclass, no interfaces). `GenericSignature.parse` prefers the field reading and falls
back to the class reading only when input remains unconsumed — documented on the `parse`
KDoc. Learned: session 3 (T-002).

### L-007 — "watch it fail for the right reason" catches wrong tests, not just missing code `process`
In T-002's first green, three tests failed: two real implementation bugs and one wrong
test expectation (L-005). The RED step validates the test as much as the code — never skip
it, and read the failure messages individually. Learned: session 3 (T-002).

### L-008 — verify "it builds" from a clean clone `process`
Local caches (`.gradle/`, `.kotlin/`) can mask breakage. Session 2's green build was
proven by cloning the public repo into a fresh directory and building there. Learned:
session 2 (T-001).

### L-009 — a data-class constructor property implementing a supertype `val` needs `override` `kotlin`
Symptom: compiler error `VIRTUAL_MEMBER_HIDDEN: 'x' hides member of supertype and needs an
'override' modifier`. Fix: declare the constructor property `override val x: T`. Bites
under explicit-API mode, where every property is written out in full. Learned: session 3
(T-002, `TypeName.ClassType.packageName`).

### L-010 — kotest `checkAll` makes expression-bodied JUnit tests non-void → silently undiscovered `kotlin`
Symptom: `./gradlew :core:test --tests ...SomePropertyTest` reports "No tests found",
and the class never appears in test results — yet it compiles. Cause: kotest 6's
`checkAll` returns `PropertyContext`, so `fun \`x\`() = runBlocking { checkAll(...) }`
infers a non-Unit return type; JUnit Jupiter only discovers `void`/`Unit` methods.
Fix: `= runBlocking<Unit> { ... }` (or a block body). Watch for it whenever a test
delegates to a generic helper — check `javap -p` on the class if discovery is silent.
Learned: session 5 (T-003).

### L-011 — plain `clikt` (mordant flavor) eagerly loads JNA; use `clikt-core` for non-interactive CLIs `kotlin`
Symptom: JDK 26 prints four `WARNING: java.lang.System::load has been called by
com.sun.jna.Native …` lines to **stderr on every run** of a Clikt 5 CLI. Cause:
`com.github.ajalt.clikt:clikt` → mordant → mordant-jvm-jna → JNA, and mordant's terminal
detection loads it during startup even when stdout is piped. Fix: depend on
`com.github.ajalt.clikt:clikt-core` (plain help formatter, `CoreCliktCommand`, same
`versionOption`/`main`/`parse` extensions) — no mordant, no JNA, ~2 MB smaller. Also:
`CliktCommand.test()` lives only in the mordant jar; for a `CoreCliktCommand` test
`parse()` and assert on the thrown `PrintMessage` instead. Learned: session 6 (T-004).

### L-012 — Gradle 9 removed/erected API the classic recipes rely on `build`
Three T-004 hits, all compile-time, all cheap to fix once recognised:
(a) `val t by tasks.registering` is an **error-level deprecation** (Gradle 9.6+) — write
`val t = tasks.register<Type>("name") { … }`.
(b) `FileCopyDetails.mode = …` no longer exists — use `details.permissions { unix("rwxr-xr-x") }`.
(c) A `Copy` task with `into(layout.buildDirectory)` declares the whole build dir as its
output and fails validation: "Task ':app:jar' uses this output of task ':app:installDist'".
Use a one-file task with `outputs.file(…)` for single-file installs. Learned: session 6
(T-004).

### L-013 — a shell script's failure tests must cover the no-coreutils PATH, not just the no-java PATH `process`
Symptom: the launcher's "no JDK" test passed, but a PATH with neither `java` *nor*
`dirname` died with `dirname: command not found` **and then a misleading error** (the
broken `dirname` emptied the jar path, so the script complained about a missing jar).
Fix: minimise external tools (POSIX parameter expansion instead of `dirname`), guard the
one that remains (`command -v sed || die`), and keep a test with a tools-only PATH.
Generalises: fault-inject the *environment* of a script, not only its inputs. Learned:
session 6 (T-004).

### L-014 — kotlinx.serialization drops default-valued properties unless `encodeDefaults = true` `kotlin`
Symptom: the `--json` envelope came out as `{"ok":…,"command":…,"result":…}` — the
`"jdx": 1` version marker silently vanished. Cause: `val jdx: Int = ENVELOPE_VERSION` is
an *optional* descriptor element, and `Json` defaults `encodeDefaults` to **false**
(despite what you may remember from older versions). Fix: `Json { explicitNulls = false;
encodeDefaults = true }` in the one shared `Json` instance. Any contract-critical field
with a default needs a test asserting its presence. Learned: session 7 (T-005).

### L-015 — an unconditional `exitProcess` in a command kills the Gradle test worker `tooling`
Symptom: `DoctorCommand.run()` ended with `exitProcess(exitCodeFor(report))`; the full
`:cli:test` then ran only 4 of 29 tests — the rest silently never executed, one reported
"skipped", no crash message. Cause: `exitProcess(0)` on the success path terminates the
test worker JVM mid-suite. Fix: `val code = exitCodeFor(report); if (code != 0)
exitProcess(code)` — a normal return already means 0. Rule: production exit mapping must
be a pure function (tested directly); only the non-zero arm may exit. Learned:
session 7 (T-005).

### L-016 — Clikt 5 `parse()` already invokes `run()` — calling both double-executes `kotlin`
Symptom: an in-process test doing `command.parse(args)` then `command.run()` printed every
line twice. Cause: `CoreCliktCommand.parse(argv)` is `parseAndRun` (unlike Clikt 4) — the
docs say "If you don't want Clikt to exit your process, call `parse` instead", and `parse`
includes `run()`. Fix: in tests, call `parse()` alone; never follow it with `run()`.
Learned: session 7 (T-005).

### L-017 — Kotlin keeps the `is` prefix on Java boolean getters `build`
Symptom: `options.debug = false` in a `JavaCompile` block fails script compilation with
"Unresolved reference 'debug'", although `CompileOptions.setDebug(boolean)` plainly exists.
Cause: Kotlin's synthetic property for a Java `isDebug()`/`setDebug()` pair is named
`isDebug`, not `debug` (same reason Android code writes `view.isEnabled`, never
`view.enabled`). Fix: `options.isDebug = false`. Rule: when a documented Gradle/Groovy
recipe does not resolve in `.kts`, check the `is`-prefix before doubting the API.
Learned: session 8 (T-006).

### L-018 — `javap` options must precede the class name `tooling`
Symptom: `javap -p -classpath foo.jar com.Example -v` fails with `Error: class not found: -v`
— it treats the trailing flag as a class name. Cause: `javap` (like `java`) parses options
only before the class operand; anything after is a class name, no error until lookup. Fix:
`javap -p -v -classpath foo.jar com.Example`. Any test shelling out to `javap` should build
the argv in that order. Learned: session 8 (T-006).

### L-019 — a custom Gradle `Test` task runs NO-SOURCE unless pointed at the test source set `build`
Symptom: a new `tasks.register<Test>("tier2Test") { includeTags("tier2") }` ran
`NO-SOURCE` in every module while `test` was green — the tier looked wired and tested
nothing. Cause: only the built-in `test` task gets `testClassesDirs`/`classpath` by
convention; a custom `Test` task starts empty. Fix: set both from the `test` source set
(`project.extensions.getByType<SourceSetContainer>().getByName("test")`) — and note the
receiver inside the `register` block is the *task*, so it must be `project.extensions`,
not bare `extensions`. Rule: any new `Test` task needs a test proving it executed
something (the soak proof test counts executions; `test-results/<task>/*.xml` shows them).
Learned: session 9 (T-053).

### L-020 — Gradle `logger.lifecycle` takes `{}` placeholders, not format specifiers `build`
Symptom: `logger.lifecycle("[tier1] total: {:.1f}s …", total)` printed the literal text
`{:.1f}` and shifted every argument one slot sideways. Cause: Gradle's `lifecycle(String,
Object...)` is SLF4J-style — only bare `{}` is substituted; anything else (`{:.1f}`,
`{:6.2f}`) is literal output. Fix: pre-format in Kotlin —
`logger.lifecycle("%.1fs".format(total))`. Learned: session 9 (T-053).

### L-021 — a `private companion` factory is invisible to other files, even `internal` callers `kotlin`
Symptom: `INVISIBLE_REFERENCE — Cannot access 'companion object Companion': it is private`
when `ArtifactLoader` called `JarArtifact.open` declared `internal` inside a `private
companion object`. Cause: visibility composes — the member's effective visibility is capped
by its container. Fix: `internal companion object` (or a top-level internal function).
Learned: session 10 (T-007).

### L-022 — kotest 6 has two `map` extensions on `Arb`; the wrong one compiles halfway `kotlin`
Symptom: `Arb.list(...).map { ... }` with `import io.kotest.property.map` fails with
`INITIALIZER_TYPE_MISMATCH … RTree<uninferred>`. Cause: that `map` is the `Tree`/`RTree`
combinator, not the generator transform — the generator one is
`io.kotest.property.arbitrary.map`. Fix: import the `arbitrary` one (same story as L-010's
`checkAll` discovery trap: kotest 6 moved things; check the package before the logic).
Learned: session 10 (T-007).

### L-023 — kotest 6 `shouldBeInstanceOf` takes an assertion lambda, not a message `kotlin`
Symptom: `result.shouldBeInstanceOf<Ok>("reader failed: $result")` fails compilation with
`ARGUMENT_TYPE_MISMATCH … '(Ok) -> Unit' was expected`. Cause: the overload after the
type parameter is an assertion block on the matched value, not a failure message — and the
no-lambda form already returns the smart-cast value via contracts, so a following `as`
is a redundant-cast warning too. Fix: `val ok = result.shouldBeInstanceOf<Ok>()` and use
`ok` directly; wrap in `withClue` when a message is really needed.
Learned: session 11 (T-008).

### L-024 — a lone-superclass class `Signature` parses as a field, silently dropping generics `jvm-spec`
Symptom: `class StringList extends ArrayList<String>` (no interfaces, no type parameters)
resolved `add(Object)` instead of `add(String)` on real bytecode. Cause:
`GenericSignature.parse` prefers the field reading when there are no type parameters, so
`as? ClassSignature` in the reader silently degraded to `null` and the substitution edge
went raw. Fix: `GenericSignature.parseClass` for class-file contexts (the attribute is a
ClassSignature by construction, JVMS §4.7.9.1); `AsmClassReader` uses it. Rule: any
`as?` on a parse result that can be `null` on *well-formed* input is a silent-drop bug —
pin the shape with a test. Learned: session 12 (T-009).

### L-025 — `git diff` every edit, and keep the anchor in both strings `process`
Symptom: an `edit` meant to *append* to `index/build.gradle.kts` *replaced* a
block instead; twice more, inserting a test before an existing one dropped the
neighbour's `@Test` line. Cause: the edit tool replaces exactly the `oldString`
given — a too-minimal `oldString` matches more than meant, and an anchor reused
for insertion is load-bearing. Fix: after any edit, `git diff <file>` before
paying for a build; when inserting adjacent to a block, the anchor text appears
verbatim in **both** `oldString` and `newString`. Learned: session 13 (T-010);
anchor cases in T-012 (L-028 merged here — same tool discipline).
