# Lessons — shard 1: L-001…L-025

Append-only lessons log, **25 entries per shard** (D-023). Rules and index live in
`docs/LESSONS.md`. Entries are never edited — a wrong lesson is corrected by a new entry.

---

### L-001 — the `libs` version-catalog accessor is out of scope inside `subprojects {}` `build`
Symptom: *"Extension with name 'libs' does not exist"* from a root `subprojects` block.
Cause: Gradle generates the catalog accessor per build script; inside `subprojects` the
receiver is a subproject that has no such extension. Fix: capture catalog values at root
scope into `val`s and reference those inside the block, or use a `buildSrc` convention
plugin (where the problem disappears entirely). Learned: session 2 (T-001).

### L-002 — this machine's `grep` is `ugrep` and misparses some flag combos `tooling`
`grep -vF '-'` silently misbehaves. Fix: invoke `/usr/bin/grep` explicitly, or prefer
Python for text processing in scripts meant to be portable. Learned: session 2.

### L-003 — `ls -la` can hang in this environment `tooling`
A shell alias intercepts it. Use `/usr/bin/ls` or `/usr/bin/find`. Learned: session 2.

### L-004 — no `gradle`/`mvn` on PATH; regenerate the wrapper from the cached dist `build`
`JAVA_HOME` is unset and no Gradle is installed — the wrapper is the only entry point. To
regenerate it, invoke the cached distribution directly:
`~/.gradle/wrapper/dists/gradle-9.7.1-bin/*/gradle-9.7.1/bin/gradle wrapper`.
Learned: session 2 (T-001).

### L-005 — `V` is legal only as a method return type, never a field type `jvm-spec`
JVMS §4.3.2–§4.3.3: `V` (void) appears only as a MethodDescriptor's return; a
FieldDescriptor may never be `V`. The first field-descriptor round-trip test wrongly
included `V` — the *test* was wrong, not the parser. Rule: when testing against a spec,
check the spec section; do not generalise from familiar syntax. Learned: session 3 (T-002).

### L-006 — `LFoo;` is ambiguous between a field signature and a class signature `jvm-spec`
JVMS §4.7.9.1: a FieldSignature (`LFoo;`) is also a valid parameterless ClassSignature
(superclass, no interfaces). `GenericSignature.parse` prefers the field reading and falls
back to the class reading only when input remains unconsumed — documented on the `parse`
KDoc. Learned: session 3 (T-002).

### L-007 — "watch it fail for the right reason" catches wrong tests, not just missing code `process`
In T-002's first green, three tests failed: two real implementation bugs and one wrong
test expectation (L-005). The RED step validates the test as much as the code — never skip
it, and read the failure messages individually. Learned: session 3 (T-002).

### L-008 — verify "it builds" from a clean clone `process`
Local caches (`.gradle/`, `.kotlin/`) can mask breakage. Session 2's green build was
proven by cloning the public repo into a fresh directory and building there. Learned:
session 2 (T-001).

### L-009 — a data-class constructor property implementing a supertype `val` needs `override` `kotlin`
Symptom: compiler error `VIRTUAL_MEMBER_HIDDEN: 'x' hides member of supertype and needs an
'override' modifier`. Fix: declare the constructor property `override val x: T`. Bites
under explicit-API mode, where every property is written out in full. Learned: session 3
(T-002, `TypeName.ClassType.packageName`).
