# Lessons — shard 2: L-026–L-050

Append-only lesson log, **25 entries per shard** (D-023). `docs/LESSONS.md` holds the
index and the rules — this file only holds entries. Never edit or renumber a past
entry; numbering is global, append-only and never reused.

---

### L-026 — clikt-core's default `exitProcess` is a no-op `tooling`
Throwing `ProgramResult(n)` and letting Clikt's `main()` "translate it to the process
exit code" exits **0**: `main()` catches `CliktError` and calls
`context.exitProcess(status)`, but in clikt-core that hook defaults to `{ }` — the
real one lives in the mordant flavor this repo excluded (L-011). Call
`kotlin.system.exitProcess` explicitly for non-zero exits (as `DoctorCommand` does),
and inject the terminator `(Int) -> Nothing` so tests can throw instead of dying.
Learned in T-011 wiring `show`/`members`/`outline` (real binary exited 0 on every error).

### L-027 — an explicit `--from X` must defeat the `Object` collapse `process`
`--from java.lang.Object` is the documented escape hatch out of the collapsed
`+ N from java.lang.Object` summary — but the collapse lives in the renderer, which
never saw the flag, so the query returned *only* the summary line it was asked to
expand. Rule: a filter that names one declaring type disables every display rule
that hides that type. Caught by the tier-2 `--from` test, not by reading.
Learned in T-011 (`JdxService` now passes `collapseObjectMembers = from != Object`).

### L-028 — inserting with `edit` must keep the anchor in both strings `tooling`
Twice in T-012, adding a test *before* an existing one used the next test's header
as `oldString` and dropped it from `newString` — silently deleting the neighbour's
`@Test` line and orphaning its body. The tool does exactly what the strings say;
it cannot know the anchor was load-bearing. Rule: when inserting adjacent to a
block, the anchor text appears verbatim in **both** `oldString` and `newString` —
and `git diff` the hunk before running anything else.

### L-029 — `java-test-fixtures` jars pollute `build/libs` scans `build`
Applying `java-test-fixtures` to `testfixtures` drops
`testfixtures-<version>-test-fixtures.jar` into `build/libs`, and every
"exactly one binary fixture jar" assertion (`Fixtures.binaryJar`, the golden
suites) instantly sees two jars and fails. The jar is a build detail no corpus
scan should ever meet. Rule: point `testFixturesJar.destinationDirectory` at
`build/test-fixtures-libs` (variant-aware consumers follow the task output),
and delete the stale jar already sitting in `build/libs`.
Learned in T-054 (17 tier-2 failures, one root cause).

### L-030 — never let a raw control character into a string literal `tooling`
Writing a JSON codec by hand, the escapes for form-feed (`\f`) and unit-separator
came out as **literal control bytes** inside Kotlin string/char literals — invisible
in every read of the file, legal-looking, and a latent source-corruption trap
(`"\u001F"` reads as `""` with an invisible guest). Kotlin has no `\f` escape
(it needs `'\u000C'`), which is how the raw byte slipped in. Rule: after writing
any escape-heavy codec, grep the file for control bytes
(`grep -n $'\x0c' file; $'\x1f' …`) and spell every non-printable as an explicit
`\uXXXX`. Learned in T-013 (`SqliteIndexStore` codecs).

### L-031 — at JDK scale, preparing statements costs more than executing them `tooling`
`replaceClasses` prepared every `INSERT` fresh per row — ~700k prepares for the
33k-class JDK, and the write pass took 14.7 s. Hoisting the 7 statements into a
per-artifact `BulkWriter` (same SQL, same bind order, same commit) halved it to
7.7 s with zero behaviour change. Rule: measure read-vs-write phases separately
before optimising an indexer; the bottleneck is fixed costs per row, not the
transaction. Learned in T-014 (scratch probe: read 5–6k/s, write 2.3k/s).

### L-032 — the running JDK ships classes our model cannot name `jvm-spec`
`java/lang/Exception$JB$$Assertion` (+ `$Event`, `$FullGC`, `$ShrinkingGC`) are
JFR-generated classes with empty `$`-separated segments, which `TypeName`
rejects — the only 4 of 33,104 JDK classes that index as `CORRUPT_CLASS`. The
degrade-with-warning path worked exactly as designed; the gap is model
strictness, not reader robustness. Rule: when the corpus contradicts the model,
file the model task (T-065) — do not loosen the reader to smuggle them in.
Learned in T-014 (full-JDK soak run).

### L-033 — never batch a read and its dependent edit in one turn `process`
Issuing `read` + `edit` together when the edit's `oldString` comes from the
read means both execute before either result returns — the edit runs blind and
mangles the file (a scratch test was rewritten mid-file and failed to compile).
Rule: reads that feed an edit get their own turn; batch only independent calls.
Learned in T-014 (owner correction).

### L-034 — kotlinc rejects `:` in backtick test names `kotlin`
Sentence-style test names (CONTRIBUTING.md) may use almost any punctuation —
except `:`: `fun \`determinism: same roots\`` fails compilation with
`Name contains illegal characters: :` (verified with a minimal probe in T-015).
Rule: use `—`, `-` or parentheses in test names, never a colon.
Learned in T-015 (`WorkspaceServiceTest`).

### L-035 — capture stdout *around* the exit-throw, not inside it `process`
A CLI test helper that assigns `output = captureStdout { parse() }` and catches
the injected exit-throw *outside* the capture loses every failure's text: the
throw skips the assignment, so all non-zero-path assertions read empty strings
(7 of my `ws` tests failed identically in T-015). Rule: put the try/catch
*inside* the capture block (as `ReadCommandsTest` already does), or capture
around the whole parse-and-catch. Learned in T-015 (`WsCommandsTest`).

### L-036 — kotest 6 builds generators eagerly: recursion must bottom out at construction `tooling`
Three ways this bites: (1) a mutually recursive `Arb` family (`arg → ref →
class → args → arg`) whose depth-0 branch still builds one more recursive layer
never terminates — `StackOverflowError` at *construction*, before a single case
runs; the depth-0 base must build nothing recursive (unbounded wildcard, bare
type variable, arg-less class). (2) There is no single-arity `Arb.bind(x) { }`
— use `x.map { }`. (3) `Arb.of(emptyList())` throws ("collection must not be
empty"); the empty case is `Arb.of(listOf(emptyList<T>()))`. Learned in T-055
(`SignatureGenerators`).

### L-037 — a null-on-malformed parser must not call a throwing constructor `jvm-spec`
`JvmDescriptor.parse` promises null-on-malformed, but its `L...;` branch handed
untrusted class-file text to `typeNameFromBinaryName`, whose `require` throws
on empty segments (`L$Entry;`) and separator garbage (`L1C)Q.;`) — so the
T-055 never-throws property failed on its first run, exactly as designed.
Rule: at the boundary where untrusted bytes become model values, catch the
model's `IllegalArgumentException` and return null (the KDoc already said
null — the code was lying). Bonus find in the same run: `void` arrays
(`[[[V`) are not types, so array-element generators must exclude `VOID`.
Learned in T-055 (production fix in `parseDescriptorType`).

### L-038 — command tests using the real workspace store are hostage to the machine `process`
`ReadCommandsTest` builds `ShowCommand` with the default `FileWorkspaceStore.system()`,
so an `active-workspace` file on the contributor's machine (left by an earlier
`jdx ws use fx` e2e) silently re-roots every "no workspace" assertion — 2 red
tests that pass nowhere-near the diff. Proven by shelving `~/.config/jdx`:
green without it, red with it. Rule: command tests must inject
`InMemoryWorkspaceStore()` (the seam exists for this); never assert defaults
through the real home directory. Filed as T-066, not fixed inside T-055.
Learned in T-055 (pre-existing T-015 gap, ambient state from a prior session).

### L-039 — Kotlin block comments nest: never write a slash-star sequence in KDoc `kotlin`
Kotlin's `/* … */` comments nest (unlike Java's), so a glob like `/*.jar`
inside a KDoc comment *opens* a nested comment that the closing `*/` then
fails to close — the file dies with `Unclosed comment` at EOF plus a
misleading `Missing '}'` somewhere far earlier (bisected to the KDoc line
only by truncating the file). Rule: in comments spell globs as separate
segments (`…/<file>.jar`), and grep new files for stray `/*` when the
compiler hallucinates about braces. Learned in T-016 (`ProjectDiscovery`).

### L-040 — a class-dir root must be a package root: keep the deepest, not the outermost `tooling`
`DirArtifact` lists entries *relative* to the opened dir, so opening
`build/classes` yields `java/main/…`-prefixed entries no binary name matches
— the query 404s with no error. The first T-016 cut kept the outermost dir
and its own end-to-end test caught it (exit 1, not 0). Rule: when several
candidate class dirs nest, keep the deepest existing one
(`build/classes/java/main` beats `build/classes`); keep a lone
`build/classes` only when no language layout exists beneath it. Learned in
T-016 (`ProjectDiscovery.deriveBinaryRoots`).

### L-041 — auto-discovery makes the checkout itself ambient test state `process`
T-016 discovery walks up from the process working directory, and under Gradle
that is a module dir inside a Gradle project — so every tier-1 command test
asserting "default roots" suddenly grew `cli/build/classes` plus a fallback
warning, and golden/service suites would have pinned it. Same family as
L-038 (ambient `~/.config/jdx`), one level sneakier because the ambient
state is the repo itself. Rule: thread the discovery seam (`ProjectDiscoveryFn`,
null-returning in tier-1, `-w`-selected tests already skip it) through every
command exactly like the `store`/`getenv` seams; pin goldens with discovery
off and cover the real path once, in tier 2. Learned in T-016
(`ReadCommandsTest`, `ReadCommandsGoldenTest`, `ReadCommandsServiceTest`).

### L-042 — kotlinc emits `$`-nested supertypes inside generic signatures: split at the model edge, not in the parser `kotlin`
A class implementing `SavedStateRegistry$SavedStateProvider` carries the
generic-signature edge `Landroidx/savedstate/SavedStateRegistry$SavedStateProvider;`
(binary `$` form, not the grammar `.Inner` suffix). `readIdentifier` keeps the
`$`, so the edge parsed with simpleName `SavedStateRegistry$SavedStateProvider`
— and `GenericRef.toTypeName` built it unsplit, tripping the `ClassType`
no-separators invariant and turning the whole query into exit 6 (first caught
by the T-056 soak on androidx jars). Rule: do **not** fix the signature
parser — it is byte-faithful and its parse→print fixed point would break
(`$` would reprint as `.`); split `$` where the signature view becomes a model
name (`GenericRef.toTypeName`, mirroring `typeNameFromBinaryName`), and return
null for still-unmappable edges — the linearisation already skips those.
Learned in T-056 (`MemberResolver.GenericRef`, `MemberResolverTest` RED first).

### L-043 — a corpus sampler must enumerate classes through `ArtifactLoader`, never raw zip entries `tooling`
The first T-056 soak sampled `ZipFile` entries directly and drew
`META-INF/versions/11/module-info.class` — a multi-release versioned entry no
binary name addresses, so the service honestly 404d it (exit 1) and the soak
failed on the sampler, not the product. Rule: sample from
`ArtifactLoader.openJar(...).classEntryPaths()`, the exact entry set queries
see (MR selection + traversal rejection included); a jar that will not open
contributes zero samples via the existing empty-list catch. Learned in T-056
(`JavapCorpusSoakTest.sampleClasses`).

### L-044 — a never-throws property over adversarial strings finds the bugs hand-written glob tests cannot `tooling`
`globToRegex` looked right with six example tests — then the 1,000-case
never-throws property failed three runs in a row, each a real Java-regex
rejection: `[F[ßN]` (nested `[` starts no legal class), `[]`/`[^]`
(empty/negated-empty classes are unclosed), `[Q-9]` (reversed range is
illegal). Each fix got pinned as an example (`degenerate classes`,
`dashes are ranges`) next to the property. Rule: any function compiling
user-influenced regex gets the never-throws property *first*, and every
shrink it produces becomes a permanent example — the property is the finder,
the examples are the documentation. Learned in T-017
(`SymbolSearchPropertyTest`, `SymbolSearch.globToRegex`).

### L-045 — prove a red build is yours before fixing it: stash and rerun `build`
Session 24's `./gradlew check` failed twice — once on the known T-066 ambient
workspace, once on configuration-cache storing — and neither was the new code:
`git stash -u` + rerun reproduced both on the clean tree in under a minute.
Rule: when a failure sits outside the files you touched, reproduce it stashed
before spending a minute diagnosing; if it reproduces, file a task (T-067 for
the cache) and verify your own work with the documented workaround
(`--no-configuration-cache`, shelved `~/.config/jdx`) instead of absorbing
someone else's bug into your task. Learned in T-017 (session 24).

### L-046 — catalog `libs` accessors do not resolve in `settings.gradle.kts` `build`
Probed 2026-09-17: `alias(libs.plugins.…)` and even `libs.versions.…` fail
settings-script compilation with "Unresolved reference 'libs'", though the
same catalog serves every module build file. Rule: settings-only plugin
versions live as literals in `settings.gradle.kts` with a comment saying so —
a single honest source beats a catalog entry no settings script can read.
Learned fixing the toolchain deprecation (session 25, Foojay resolver).

### L-047 — config-cache "problems storing" are diagnosed from the report JSON, not the console `build`
The console says only "2 problems found"; the per-build
`build/reports/configuration-cache/*/…/configuration-cache-report.html`
embeds `// begin-report-data` JSON whose `diagnostics[].trace` names the exact
task, field and synthetic class (`Build_gradle$1$1`, `this$0`). Rule: extract
that JSON first — here it named `:app:installDist` (`layout` in `doLast`) and
`:verifyTier1Budget` (`subprojects` + a script-level budget in `doLast`) in
minutes. The fix pattern is always the same: capture plain values as locals at
configuration time, never touch project/script state from an action. Learned
closing T-067 (session 25).

### L-048 — root flags need a full context-chain walk, not one parent lookup `kotlin`
`effectiveJson` read `currentContext.parent?.command as? JdxCli`: flat commands
(`doctor`) worked, grouped ones (`ws list`, `cache info`) silently dropped
root `--json` — unit tests only covered the flat shape, so the real launcher
e2e caught it (`jdx --json cache info` printed text). Rule: whenever a command
grows a group level, re-check every `parent?.command` lookup, and pin the
root-position flag through the group in a test. Fixed with `rootCommand()` in
`JdxCli.kt` (session 25, T-018).

### L-049 — a stale provisioned JDK keeps the toolchain deprecation alive after you declare Foojay `build`
Declaring the Foojay resolver did not silence "installed via auto-provisioning
without toolchain repositories": the warning names how the *cached* JDK was
installed, so the stale `~/.gradle/jdks/jetbrains_*` entry (moved to
`/tmp/stale-jdk-backup`, restore if a provision is ever needed) had to go —
then the local `/usr/lib/jvm/java-21-openjdk` auto-detected and the diagnostic
vanished with no download. Rule: toolchain warnings describe cache state, not
just build files; inspect `~/.gradle/jdks` and `javaToolchains` before editing
build scripts. Learned in session 25.
