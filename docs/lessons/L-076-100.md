# Lessons — shard 4: L-076…L-100

Append-only lesson log, **25 entries per shard** (D-023). Rules and index live in
`docs/LESSONS.md`. Entries are never edited.

---

### L-076 — Options types asserted with `shouldBe` need value equality `process`
Adding a `decompiler: DecompilerEngine` field to `BodyOptions` broke every CLI
test that captures options with `shouldBe BodyOptions(…)`: two default engine
instances were never `==`. The fix was making the value types data classes
(`DecompileCache`, `VineflowerDecompiler`), not touching the tests. Rule: any
options/config holder compared in tests must have value equality — default to
`data class` for holders, and treat a hand-rolled class there as a smell.
Learned in session 45 (T-026).

---

### L-077 — `javap` prints no blank line between the class header and the first member `tooling`
Blank-line block splitting swallowed the first member into the `Compiled
from`/class-decl header block (the ctor section vanished; the test caught it
before review). `javap` separates *members* with blanks but not the header
from the first member. Fix: filter `Compiled from` / `{`-ending / `}` lines
first, then blank-split the rest. Sibling gotcha in the same task: `javap
-version` prints to stdout on JDK 26 (stderr on older JDKs) — always read the
merged stream. Learned in session 46 (T-027).

---

### L-078 — JavaParser hides declarations outside the member list `tooling`
A bytecode-vs-sources member comparison over `TypeDeclaration.members` missed
two declaration sites and flagged every record and annotation type as
mismatched: record components live in the header (`RecordDeclaration`
implements `NodeWithParameters` — read `parameters`, there is no `entries`),
and annotation elements are `AnnotationMemberDeclaration`, not
`MethodDeclaration`. Rule: any source-member enumeration must cover header
parameters and annotation members, or the comparison lies. Caught by the
matched-fixture silence test before review. Learned in session 47 (T-028).

---

### L-079 — constructors carry hidden leading parameters the source never spells `jvm-spec`
Enum constructors take implicit `(String name, int ordinal)` before the
declared parameters, and inner-class constructors take the enclosing instance
first (`Nesting$Inner(Nesting)` for a source-declared default). A
bytecode-vs-source arity check must strip those prefixes (enum
`(String, int)`, a leading outer-class parameter on nested types) or every
enum/inner type reads as stale. `javap -s` shows the real descriptors, which
is how the shapes were confirmed. Learned in session 47 (T-028).
