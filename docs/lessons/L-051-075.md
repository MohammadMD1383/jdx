# Lessons — shard 3: L-051–L-075

Append-only lesson log, **25 entries per shard** (D-023). `docs/LESSONS.md` holds the
index and the rules — this file only holds entries. Never edit or renumber a past
entry; numbering is global, append-only and never reused.

---

### L-051 — Metamorphic inheritance relations must track collapse and timestamp non-determinism `process`
When checking `members(T, --inherited) ⊇ members(super(T), --inherited) minus private/overridden`,
a member declared on an ancestor `D` of `super(T)` may be overridden or shadowed by an
intermediate type or interface of `T` that is visited earlier in BFS linearisation. The
metamorphic check must inspect `overriddenTypes` and `hiddenTypes` (where `MemberResolver` records
collapsed declarations) rather than requiring `declaringType == D`. Additionally, when asserting
`index(jar) twice ⟹ byte-identical rows`, `StoredArtifact.indexedAt` captures creation wall-clock
time and must be normalised (`copy(indexedAt = 0)`) before comparing stored metadata rows.
Learned in session 27 (T-058).

### L-052 — Data-class equality does not survive function-typed fields `kotlin`
`JdxService.RootsSpec` gained a `mavenResolve` function field, and existing command
tests assert it by value — a fresh `{ text, fetch -> ... }` lambda per
`resolveRoots` call breaks every one of them (lambdas compare by identity).
Keep the production `::functionReference` when no test seam is injected and only
allocate the closure when custom repositories/fetcher are passed. In general: a
function-typed field on a data class asserted by value needs a canonical instance.
Learned in session 28 (T-019).

### L-053 — Prove network code without the network `tooling`
`MavenFetch` takes a `Fetcher` function: unit tests serve canned bytes + `.sha1`
bodies (mismatch, missing, malformed, download-failure), one tier-1 test serves
both through a real loopback `HttpServer` so the production `httpGet` path
(redirects, status codes, cap) is covered in milliseconds, and resolver tests
point `repoBaseUrl` at `http://unused.invalid` so a test that accidentally hits
the network fails fast with DNS instead of hanging. Live Central proof stays a
manual e2e step, not a test. Learned in session 28 (T-019).

### L-054 — Text⊆JSON containment checks must compare JSON-side escaped `tooling`
A soak/parity check asserting "every text entity appears in JSON" via
`json.contains(signature)` fails on the first constant-valued field it meets:
text prints `String X = ":status"` while JSON carries `"signature":"… = \":status\""`.
Compare against `JsonEscape.quote(entity)` minus its surrounding quotes (core's
escaper is public, reuse it — never hand-roll a second one). The same trap
waits in annotation `default ""` clauses and any future `"`-carrying rendering.
Learned in session 29 (T-059): the harness's first real-corpus run flagged 20
such "missing" entities, all escaping, none a production bug.

### L-055 — PIT minions don't inherit the `test` task's system properties `tooling`
PIT forks fresh minion JVMs: `systemProperty("jdx.fixturesDir", …)` on `test`/`tier2Test`
never reaches them, so fixture-corpus tests fail under `:index:pitest` with "jar missing"
while passing everywhere else. Forward the property explicitly via the `pitest {}` block's
`jvmArgs` (an absolute path is fine — PIT runs locally, never in a relocatable cache
entry). Symptom to recognise: green `check`, red `pitest`, same tests. Learned in
session 30 (T-060).

### L-056 — A scoped PIT probe report is not a module report `tooling`
`-PpitestScope='<glob>'` narrows `targetClasses`/`targetTests` for fast single-mutant
iteration — but the HTML report it leaves behind claims whole-module numbers for a
10-class slice (and `mutations.xml` may be empty if the run was interrupted). Never quote
a scoped report as the module's score, and never leave one in the tree as if it were the
full run: re-run unscoped before closing the task. Found in session 30 (T-060): the WIP's
`index` report covered only the `artifact` package until the full 1,705-mutant run
replaced it.

### L-057 — Golden fixtures must visibly differentiate the new behaviour `process`
First `SortOrdersGoldenTest` draft pinned `Generics` (single group, alphabetical
members) and `Nesting$Inner` (2 rows): all three `--sort` orders rendered
byte-identical files — 12 goldens that prove the flags are accepted but pin no
ordering. Caught only because I diffed the orders against each other before
committing. Fix: `TrafficLight$1` (enum-constant body inheriting from
`TrafficLight` — `declaring`≠`kind`, `name` reorders fields first) carries the
differentiation; `Generics` stays as the honest no-op pin, said so in the test
KDoc. Rule: after `golden.update`, diff the new files against each other, not
just against empty — identical outputs across modes that should differ are a
test deleted. Learned in session 31 (T-062).

### L-058 — A promoted helper must name the copies that must mirror it `process`
When a triplicated helper is consolidated (T-063: `fixtureBinaryJar` →
`dev.jdx.testsupport.fixtures.FixtureJars`), not every copy can or should switch
to it: core's `Fixtures` stays because its test source set is deliberately
dependency-light (T-055) and its D-017 marker helpers are the T-006 corpus
contract. Two copies of the same logic in one repo is the steady state — the fix
is not a third attempt at dedupe but a KDoc on each copy naming the other and the
rule "change one, change both" (tests pin the same behaviour on both sides).
Without that pointer, the next contributor "fixes" one and silently diverges the
other. Learned in session 32 (T-063).

### L-059 — Indexer benchmarks must run under the runtime JDK, not the toolchain JDK `tooling`
Gradle tests run on the toolchain JDK 21, while `jdx` ships for the runtime JDK
26 — and `AsmClassReader` rejects class files newer than the *running* JDK by
design. Benchmarking `minecraft-client.jar` (major 69) from a Gradle test
indexes 0 classes with 10,952 `UNSUPPORTED_CLASS_VERSION` warnings and looks
like a catastrophic regression; it is the harness running on the wrong JVM. Run
such harnesses as a plain `java -cp index+core+asm+sqlite-jdbc` under
`/usr/lib/jvm/default` (plus `asm-tree`/`asm-util`, which the reader needs at
runtime), with a fresh temp store per measured run — and never commit the
harness: permanent benchmarks belong to T-050's `bench` context. Learned in
session 33 (T-064).

### L-060 — Matchers on exception message text must mirror the producer string exactly `kotlin`
Routing a caught failure by `message.contains(...)` (T-065: empty-segment mapping
failures → `UNNAMEABLE_CLASS`, everything else → `CORRUPT_CLASS`) only works when
the matched string is the producer's exact text. A second disjunct matching no real
message (`"empty nesting segment after"` vs `TypeName`'s actual `"empty name
segment in ..."`) is dead code that pretends to widen coverage — and a future
rewording of the producer silently re-routes real cases into the wrong bucket.
Fix: quote the producer's string verbatim, keep the matcher to one disjunct, and pin
both sides of the fork with tests (unnameable-not-corrupt *and*
corrupt-stays-corrupt). Learned in session 34 (T-065).

### L-061 — Redundant `.`/`..` path decorations only compose from the base path `process`
Generating "same file, different path string" test inputs (T-068's dedupe property)
by *chaining* decorations breaks silently: `A/./f.jar`'s parent is `A/.`, so the
next hop resolves `A/./.././f.jar` → `A/f.jar`, which does not exist — the query
then exits 5 ("no such artifact") and looks like a dedupe bug. Each decoration must
be derived from the *original* directory (`A/./f.jar`, `A/../A/f.jar`), never from an
already-decorated path; composing several genuinely-redundant forms in one root list
is the stronger property anyway. Related trap: a workspace glob stored relative
(`*.jar`) resolves against the process CWD, not the workspace file — fixtures
fabricating workspaces must anchor globs absolutely or the query misses from the
wrong directory. Learned in session 36 (T-068).

### L-062 — New flag dimensions must default to the injected seam, not the production default `process`
Extending `resolveRoots` with `--repo` while tests inject `Repositories` + a
must-not-fetch `Fetcher` breaks silently if the new code unconditionally
overwrites the injected base URLs with the production default: existing tests
keep passing (both are Central today) but the seam loses meaning and a future
test injecting a custom mirror gets clobbered. Fix: when the new dimension is
empty, keep `mavenRepositories?.repoBaseUrls`; only build the combined order
when custom repos are actually in play. Same rule generalises: a new parameter
on a seam-injected function defaults to "whatever the seam says". Learned in
session 37 (T-069).

### L-063 — `ZipFile` reads do not verify entry CRCs `tooling`
Flipping a byte inside a STORED entry's data (keeping the declared CRC) reads
back corrupted *without throwing* on this machine's JDKs (21 and 26): the CRC
is evidently not checked on the `getInputStream` → `readBytes` path, so a
"CRC-corrupt entry" fault test fails — the read succeeds and the corrupt text
goes to the parser instead. To pin a read-failure branch deterministically,
corrupt the *framing* instead: zeroing the zlib header (CMF) of a DEFLATED
entry throws `ZipException` on first read while the central directory (and
hence the listing) stays intact. Learned in session 40 (T-021).

### L-064 — Never run two Gradle builds in one checkout concurrently `build`
A background `soak --rerun-tasks` racing a foreground `check --rerun-tasks`
in the same working tree fails fast (~18 s) in ways neither fails alone —
shared build dirs, test-result XML and fixture jars are not safe under two
writers. The rerun soak then passes cleanly solo (3m 51 s). Serialize
long-running Gradle invocations; if a failure only reproduces alongside
another build, suspect the orchestration before the code. Learned in session
40 (T-021).

### L-065 — `ErrorResult.Generic` rejects exits 1/2 by construction `kotlin`
`Generic`'s `require(exitCode in 3..6)` turned my T-022 "no sources" exit-1
path into an `IllegalArgumentException` → exit 6 at runtime: the only symptom
was a failing test asserting exit 1. The contract (D-015) is enforced in the
type, which is good — but it means a *message-carrying* exit-1 needs its own
shape, not a repurposed `Generic`. Fix was a nullable `detail` on `NotFound`
(second text line + appended JSON message, candidates untouched). When a
closed error hierarchy throws on your new call site, extend the hierarchy;
do not widen the `require`. Learned in session 41 (T-022).

### L-066 — Stale test-result XML outlives the compile that failed `build`
After editing a test, `:core:test` reported the *old* failures from
`build/test-results/test/*.xml`: `compileTestKotlin` had failed (a missing
`Arb.map` import), so the test task never ran and the XML on disk was stale.
Reading the XML without checking the task outcome sends you debugging code
that no longer exists. Rule: trust the task result first (`BUILD FAILED` +
which task), XML second; and with kotest-property, `map`/`flatMap` need
explicit `io.kotest.property.arbitrary.*` imports (they are not on `Arb`
itself in kotest 6). Learned in session 41 (T-022).

### L-067 — The ambient workspace explains "impossible" CLI misses `process`
A `jdx body java.util.ArrayList#...` miss with no detail line looked like a
service bug — until `doctor` showed the ambient `fx` workspace
(`include_jdk = false`, a CWD-relative glob) was selected: the JDK was never
in the roots, so exit 1 bare was *correct*. `user.home` comes from the OS
passwd entry, not `$HOME`, so `HOME=/tmp/x` does not deselect it. When the
CLI misses what the tests find, check `jdx doctor`'s workspace row (and the
CWD-relative glob trap from L-061) before touching the service. Learned in
session 41 (T-022).

### L-068 — `split('\n')` on a newline-terminated file invents a phantom last line `tooling`
Almost every source file ends with `\n`, so `text.split('\n')` yields a
trailing `""` element — a 38-line file reports 39 lines and prints `1-39`,
off by one against every editor. T-023's first green run caught it only
because the test asserted the exact `1-38` header (the golden suite, written
first with its own split, happily pinned `1-39`). Rule: the file→lines
reader drops a single trailing empty element, in exactly one shared helper
(`JdxService.readSourceLines`) that production and goldens both call — never
a parallel split in test code. Member ranges from JavaParser are unaffected
(no declaration covers the dropped line). Learned in session 42 (T-023).

### L-069 — Reusing a seam must re-check every degradation branch the old caller filtered `process`
`SourceRoot.findSource` returns the `.kt` path when that is all a root holds;
T-022 never noticed because it calls `findJavaBodies`, which maps that case
to `NotJava` before T-022 sees it. T-023 calls `findSource` directly for
whole-file serving, so the `.kt`-only crafted test came back exit 0 serving
Kotlin text as a Java answer — bypassing the T-039 degradation `body`
honors. Fix was an explicit `.kt` check at the new call site. Rule: when you
reuse a seam below the level the old caller used, enumerate the seam's full
result space (`NoSource`/`NotJava`/absent-path here) and handle each — the
old call path may have filtered branches you never saw. Learned in session
42 (T-023).

### L-070 — Whole-output `shouldNotContain` fails on words the file legitimately contains `tooling`
The T-023 D-017 test asserted `shouldNotContain "Exception"` on a whole-file
render — but `StaticInitMarker.java` catches `Exception` in its own
`<clinit>` text, so the assertion failed on correct output. (T-022's version
held only because a 3-line body slice happened not to contain the word.)
Rule: negative substring assertions are valid only when the word cannot
appear legitimately; for D-017 the proof is exit 0 plus the absent marker
file, never the absence of a word. Learned in session 42 (T-023).

### L-071 — Never zip a sorted view against its unordered source `process`
`canonicalMemberRefs` returned refs `.sorted()` for stable ambiguity lists;
`executeSignature` zipped that list against declaration-ordered bytecode
matches to build its entries — swapping `:return` suffixes (and field/method
refs) whenever the two orders differed. `body` never noticed: it only reads
`singleOrNull()` off the sorted list, where alignment is trivial. The golden
diff caught it (bridge JSON showed `Child copy()` carrying a `:Base` ref).
Rule: a sorted view must never be positionally paired with its source — pair
in source order (`orderedMemberRefs`), then sort the pairs if display needs
it. Learned in session 43 (T-024).

### L-072 — Kotlin nests block comments: never write a literal `/**` inside KDoc `kotlin`
A `/** … */` example inside a KDoc comment re-opens nesting, so the first
`*/` closes only the inner comment and the file ends "Unclosed comment".
`*\` + `/` dodges nothing — the opener is the problem, not the closer. Rule:
reword (say "javadoc comment"), never illustrate delimiter syntax inside KDoc.
Learned in session 44 (T-025).

### L-073 — `when` over a sealed result must list every branch, even as a statement `kotlin`
Two `when (val found = …)` statements over the `sources` sealed results failed
the build with NO_ELSE_IN_WHEN until every subtype had a branch — including
branches unreachable for that query (member lookup can never yield
`TypeNotFound`). Statement position grants no leniency here. Rule: when a seam
gains a subtype, fix every `when` over it the same commit; mark unreachable
branches with a one-line "kept for exhaustiveness" comment. Learned in session
44 (T-025).

### L-074 — Split unknown vs undocumented in the seam, don't re-derive it outside `process`
`findTypeDoc` first returned one `TypeNotFound` for "no such type" and "no
comment" together; the service then had to re-derive which one from file
existence — a second opinion that disagrees on stale pairings. Splitting the
seam (`TypeNotFound` vs `TypeUndocumented`) made both call sites trivially
correct. Rule: when one result case drives two different exit details, it is
two cases — push the distinction to the layer that owns the facts. Learned in
session 44 (T-025).

### L-075 — Vineflower's builder API reports directory outputs via `saveClassFile` `tooling`
`Decompiler.builder().inputs(DirectoryContextSource)` never calls
`saveClassEntry` — directory sources report through `saveClassFile`, and the
result map is keyed by slash-joined qualified names. Related: the
`SingleFileContextSource` is package-private, so single-class decompile means
staging the bytes to a temp dir at the binary path and wrapping it in a
`DirectoryContextSource(null, dir)`. Rule: probe a new third-party API with a
throwaway `javac`/`java` program before writing production code around it —
both facts above came from a 10-minute probe, not from reading bytecode.
Learned in session 45 (T-026).
