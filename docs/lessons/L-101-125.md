# Lessons — shard 5: L-101…L-125

Append-only lesson log, **25 entries per shard** (D-024). Rules and index live in
`docs/LESSONS.md`. Each entry is the mistake already paid for, kept short so the
next contributor does not pay again.

---

### L-101 — on a stdio transport, stdout is the protocol: silence every banner
kotlin-logging prints `initializing... active logger factory: ...` to
**stdout** on first use (`KotlinLoggingConfiguration.logStartupMessage`,
default true) — one stray line before the first JSON-RPC message breaks
every MCP client handshake. The T-043 server sets it `false` before creating
the transport; slf4j with no binding stays silent (its one warning goes to
stderr, which is fine). Rule: any process whose stdout is a protocol must
audit every dependency for stdout writes at startup, not just its own
`println`s — loggers are the usual suspects. Learned in session 70 (T-043).

### L-102 — `awaitCancellation` never returns on stdin EOF: await the transport close
The SDK sample keeps a stdio server alive with `awaitCancellation()` — but
when the MCP client goes away (stdin EOF) nothing cancels that scope, so the
process lingers: one leaked JVM per disconnected session. The T-043 server
awaits the transport's `onClose` instead, then closes the server (bounded —
`withTimeoutOrNull`) and returns, and the CLI blocking entry calls
`exitProcess(0)` after serving: the process exists only to serve, and one
live run in ~20 lingered with stdout already closed but the JVM alive. Rule:
for spawned child-process servers, the transport close — not cancellation —
is the shutdown signal; prove it by closing stdin and waiting on the exit
code, repeatedly (the linger is a race). Learned in session 70 (T-043).

### L-103 — a total adapter turns your fake's throw into an exit-6 line: suspect the fake first
`ErrorResult.generic` `require`s its code into 3..6 — building an exit-1
fake outcome with it throws inside the fake, and `jdx batch`'s per-line
try/catch (correctly) renders that as an exit-6 `unknown` envelope. The
failure then reads as "dispatch returned 6" when nothing under test ran at
all. Rule: when a total adapter reports exit 6 on a line your fake should
have answered, check the fake's construction (`require`, `error`, `!!`)
before the code under test — and prefer the honest constructors
(`notFound`/`ambiguous` for 1/2) over `generic`. Learned in session 72
(T-045).

### L-104 — parity-property generators must filter the adapters' routing keys
`query` and `workspace` are routing on the MCP/HTTP side (the subject and
the root selection: `splitArgs` consumes `query`, `effectiveWorkspace`
consumes `workspace`) but inert wire params to `JdxService.dispatch`
(which reads only its named option keys). A hostile-params generator that
emits them compares *different queries* across adapters and reds for no
product reason. Rule: when one reference fans out to several adapters,
generate only the shared wire vocabulary — filter routing keys (and
document why) before asserting byte equality. Learned in session 73
(T-046).

### L-105 — count lines POSIX: one trailing newline is a terminator, not a line
`"a\nb\n".split("\n")` is `[a, b, ""]` — three items for two lines. A
line-cap oracle written as a naive split disagrees with an implementation
that drops the single trailing empty (POSIX: a line *ends* with `\n`)
whenever a generator emits a trailing empty line (`Arb.list` of lines can
end in `""`, which joins into exactly that shape). The T-047 property
caught it at attempt 39. Rule: in every line-counting spec *and* its oracle,
state the trailing-newline rule up front (split, then `dropLast(1)` iff the
last is empty and size > 1) — and empty text has no lines at all, so it
never earns a footer. Learned in session 75 (T-047).

### L-106 — a self-referential lint rule flags its own implementation `build`
The T-052 bare-`TODO` rule first fired on the rule's own source: the line
`line.contains("TODO")` and the violation message naming `TODO/FIXME` have
no `T-nnn` on them. Rule: any check that scans its own codebase must carry
its owning task reference on every line that names a marker — here a
`// T-052` comment and `(rule owned by T-052)` in the message. More
generally: run a new gate once *before* trusting it green — its first hit
is usually itself. Learned in session 76 (T-052).

### L-107 — never merge `DumpLoadedClassList` outputs from two JVM runs `tooling`
Two training runs (`--version` + `help`) merged with `sort -u` break
`-Xshare:dump` with `Duplicated ID … class list format error`: lambda-proxy
lines carry run-specific `id: NNN` suffixes, so the same class appears twice
with conflicting ids. Fix: train a SINGLE run — pick the command with the
broadest measured class set (`members java.util.HashMap --limit 5
--no-daemon`, ~3.3k classes here) instead of merging. Learned in session 77
(T-048).
